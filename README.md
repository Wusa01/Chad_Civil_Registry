📌 نبذة عن المشروع

Chad Civil Registry هو مشروع نظام رقمي لإدارة السجل المدني في تشاد، مبني باستخدام Python وFlask، ويهدف إلى تنظيم وإدارة بيانات المواطنين ووثائق الأحوال المدنية بطريقة آمنة وقابلة للتوسع.

يدعم النظام إدارة:

- 👶 المواليد.
- 💍 الزواج.
- ⚰️ الوفيات.
- 💔 الطلاق.
- 👤 بيانات المواطنين.
- 🏢 مراكز ومكاتب السجل المدني.
- 📄 إصدار الوثائق والتحقق منها.
- 🗄️ الأرشفة الرقمية.
- 📊 التقارير والإحصائيات.
- 💾 النسخ الاحتياطي.
- 👥 المستخدمين والصلاحيات.

يهدف المشروع إلى تقديم نموذج عملي للتحول من الإجراءات الورقية التقليدية إلى إدارة رقمية أكثر تنظيماً، تساعد على تحسين حفظ السجلات وتسهيل الوصول إلى المعلومات وإصدار الوثائق.

🖥️ تشغيل نسخة Windows

يستهدف المشروع توفير نسخة Windows جاهزة للاستخدام، بحيث يتمكن المستخدم من تشغيل التطبيق دون الحاجة إلى تثبيت Python أو إعداد بيئة برمجية أو تنفيذ أوامر يدوياً.

طريقة التشغيل

1. الحصول على حزمة Windows من قسم "Releases"(https://github.com/Wusa01/Chad_Civil_Registry/releases)
2. تثبيت الحزمة أو تشغيل النسخة التنفيذية وفق تعليمات الإصدار.
3. تشغيل التطبيق.
4. يفتح التطبيق واجهته في متصفح الإنترنت الافتراضي.

معلومات مهمة عن طريقة التشغيل الحالية:

- يعمل التطبيق محلياً على الجهاز.
- يبدأ تشغيل خادم Flask المحلي عند تشغيل البرنامج.
- تُفتح واجهة النظام في متصفح الإنترنت الافتراضي.
- عنوان التشغيل المحلي الحالي هو:

http://127.0.0.1:5000/

- لا يعني التشغيل المحلي أن النظام متاح تلقائياً عبر الإنترنت أو الشبكة المحلية؛ يتطلب ذلك إعداداً إضافياً.

«ملاحظة: أسماء ملفات التثبيت والحزم تعتمد على ملفات الإصدار المنشورة فعلياً في GitHub Releases.»

🚀 تشغيل المشروع للمطورين

هذا القسم مخصص للمطورين الذين يرغبون في تشغيل الكود المصدري وتطوير المشروع.

1. استنساخ المشروع

git clone https://github.com/ABDELKERIMALI/Chad-Civil-Registry-Desktop.git

ثم الانتقال إلى مجلد المشروع:

cd Chad-Civil-Registry-Desktop

2. إنشاء البيئة الافتراضية

يفضل استخدام بيئة افتراضية منفصلة:

python3 -m venv .venv

تفعيلها على Linux:

source .venv/bin/activate

وعلى Windows:

.venv\Scripts\activate

3. تثبيت المتطلبات

بعد تفعيل البيئة:

pip install --upgrade pip

ثم:

pip install -r requirements.txt

4. إعداد متغيرات البيئة

انسخ ملف:

.env.example

إلى:

.env

باستخدام:

cp .env.example .env

ثم قم بتعديل القيم بما يناسب بيئة التشغيل.

مثال:

SECRET_KEY=change-this-secret-key
DATABASE_URL=sqlite:///civil_registry.db

«لا تقم برفع ملف ".env" الحقيقي إلى GitHub.»

5. قاعدة البيانات

يستخدم النظام SQLAlchemy للتعامل مع قاعدة البيانات.

في بيئة التطوير الحالية يمكن استخدام SQLite.

ملف قاعدة البيانات موجود عادةً داخل:

instance/

مثال:

instance/civil_registry.db

6. إنشاء قاعدة البيانات

عند تشغيل:

python run.py

يقوم التطبيق بإنشاء الجداول المطلوبة في بيئة التطوير عند الحاجة من خلال:

db.create_all()

7. إنشاء حساب المدير الأول

يوفر النظام مسار إعداد أولي للمستخدم الإداري:

/auth/setup

بعد تشغيل التطبيق، يمكن الوصول إليه من المتصفح:

http://127.0.0.1:5000/auth/setup

بعد إنشاء حساب المدير، يجب تأمين أو تعطيل مسار الإعداد الأولي في بيئة الإنتاج وفق تصميم النظام.

8. تشغيل التطبيق

بعد تثبيت المتطلبات وإعداد البيئة:

python run.py

سيعمل التطبيق على:

http://127.0.0.1:5000

وبحسب إعدادات التشغيل الحالية يستمع التطبيق على:

0.0.0.0:5000

مما يسمح بالوصول إليه من أجهزة أخرى على الشبكة عند إعداد الشبكة والجدار الناري بشكل صحيح.

🧪 بيئة التطوير

التطبيق يتم تشغيله حالياً باستخدام:

create_app('development')

وهذا يعني أن إعدادات التطوير تستخدم عند تشغيل:

python run.py

قبل استخدام النظام في الإنتاج يجب إنشاء إعداد Production مناسب.

🔄 Database Migrations

يستخدم المشروع:

- Flask-Migrate
- Alembic

لإدارة تغييرات بنية قاعدة البيانات (Schema).

الأوامر الأساسية:

تهيئة migrations:

flask db init

إنشاء Migration:

flask db migrate -m "describe changes"

تطبيق Migration:

flask db upgrade

الرجوع إلى Migration سابقة:

flask db downgrade

«استخدم migrations بعناية، خصوصاً في بيئة الإنتاج، وبعد أخذ نسخة احتياطية من قاعدة البيانات.»

🔧 أداة إصلاح قاعدة البيانات

يحتوي المشروع على:

fix_db.py

وهو سكربت مساعد لإجراء بعض تعديلات Schema على قواعد بيانات SQLite القديمة.

يتعامل السكربت مع بعض الحقول المرتبطة بسجلات:

- Births
- Marriages
- Deaths
- Divorces

مثل بيانات الشهود والمحكمة وبعض معلومات الطلاق.

هذا السكربت مخصص للمساعدة في عمليات الانتقال والإصلاح، وليس بديلاً عن نظام migrations منظم.

🐛 Troubleshooting

المشكلة: ModuleNotFoundError

تأكد من تفعيل البيئة الافتراضية:

source .venv/bin/activate

ثم:

pip install -r requirements.txt

المشكلة: قاعدة البيانات لا تعمل

تحقق من وجود:

instance/

وتحقق من إعدادات:

DATABASE_URL

داخل:

.env

المشكلة: تغييرات قاعدة البيانات لا تظهر

استخدم migrations:

flask db migrate -m "update database"
flask db upgrade

ولا تعتمد على:

db.create_all()

لتحديث الجداول الموجودة.

المشكلة: PDF باللغة العربية يظهر بشكل غير صحيح

تأكد من توفر الخطوط والمكتبات المطلوبة:

arabic-reshaper
python-bidi
ReportLab
WeasyPrint

كما يجب التأكد من استخدام خط يدعم اللغة العربية.

🏭 توصيات الإنتاج

هذه النسخة من المشروع موجهة حالياً إلى التطوير، ولذلك قبل استخدامها في بيئة إنتاج حقيقية يجب تنفيذ مجموعة من الإجراءات الأمنية والتشغيلية.

1. تغيير SECRET_KEY

لا تستخدم مفتاحاً بسيطاً أو معروفاً.

استخدم قيمة عشوائية قوية.

2. تعطيل Debug

في بيئة Production يجب ألا يعمل التطبيق باستخدام:

debug=True

3. استخدام Web Server

يفضل تشغيل Flask خلف WSGI Server مثل:

Gunicorn

مع:

Nginx

أو بيئة تشغيل إنتاجية مكافئة.

4. تفعيل HTTPS

يجب استخدام HTTPS لحماية:

- كلمات المرور.
- الجلسات.
- بيانات المواطنين.
- الوثائق.
- رموز التحقق.

5. حماية قاعدة البيانات

يجب:

- منع الوصول المباشر إلى ملف قاعدة البيانات.
- إنشاء نسخ احتياطية.
- تشفير النسخ الحساسة.
- اختبار استعادة النسخ الاحتياطية.

6. حماية حسابات الإدارة

يوصى باستخدام:

- كلمات مرور قوية.
- المصادقة الثنائية (2FA).
- مبدأ أقل الصلاحيات.
- تسجيل العمليات الحساسة.

7. حماية الأسرار

لا تضع ملف:

.env

أو كلمات المرور أو مفاتيح API داخل Git.
