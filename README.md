نبذة عن المشروع

نظام السجل المدني التشادي هو تطبيق ويب يهدف إلى تنظيم وإدارة بيانات السجل المدني، وتسهيل إجراءات تسجيل الوقائع المدنية وإصدار الوثائق الرسمية.

يأتي المشروع استجابةً للحاجة إلى تطوير أساليب إدارة بيانات المواطنين والحد من الاعتماد على الإجراءات الورقية التقليدية، من خلال توفير منصة رقمية تجمع بين إدارة السجلات، وأرشفة الوثائق، وإصدار الشهادات، وإمكانية التحقق منها إلكترونياً.

المشروع نموذج تقني قابل للتطوير والاختبار، وليس نظاماً حكومياً معتمداً أو مطبقاً على المستوى الوطني.

الوظائف الرئيسية

إدارة السجل المدني

- تسجيل بيانات المواطنين وإدارتها.
- تسجيل المواليد والوفيات.
- تسجيل حالات الزواج والطلاق.
- تنظيم السجلات والبيانات المدنية.

إدارة المستخدمين والصلاحيات

يدعم النظام أدواراً مختلفة للمستخدمين، منها:

الدور| الصلاحيات العامة
"admin"| إدارة النظام والمستخدمين والإعدادات
"region_mgr"| إدارة ومتابعة العمليات على مستوى المنطقة
"officer"| تنفيذ معاملات السجل المدني
"citizen"| الوصول إلى بوابة المواطنين والخدمات المتاحة

الوثائق والأرشفة

- إنشاء الوثائق بصيغة PDF.
- إنشاء رموز QR مرتبطة بالوثائق.
- التحقق الإلكتروني من الوثائق.
- أرشفة السجلات والوثائق.
- متابعة التقارير والبيانات.

بوابة المواطنين

يوفر النظام بوابة إلكترونية للمواطنين عبر المسار:

"/citizen"

وذلك للوصول إلى الخدمات المتاحة للمواطن ضمن صلاحيات النظام.

التحقق من الوثائق

يدعم النظام آلية للتحقق من الوثائق باستخدام رمز تحقق مرتبط بالوثيقة ورمز QR.

مسارات التحقق:

- صفحة التحقق:
  "/documents/verify/<TOKEN>"
- واجهة التحقق البرمجية:
  "/documents/api/verify/<TOKEN>"

تتيح هذه الآلية الوصول إلى معلومات التحقق المرتبطة بالوثيقة دون الحاجة إلى التعامل المباشر مع قاعدة البيانات.

واجهة النظام واللغات

يدعم النظام اللغتين:

- العربية.
- الفرنسية.

كما يستخدم أدوات لمعالجة النصوص العربية واتجاه الكتابة من اليمين إلى اليسار، بما يساعد على عرض الوثائق والمحتوى العربي بصورة مناسبة.

الأمان وإدارة الوصول

يتضمن المشروع مجموعة من الأدوات والآليات الأمنية، من بينها:

- Flask-Login لإدارة جلسات المستخدمين.
- Flask-Bcrypt لتجزئة كلمات المرور.
- Flask-WTF للحماية والتحقق من النماذج.
- PyOTP لدعم المصادقة الثنائية.
- PyJWT للتعامل مع رموز JWT.
- متغيرات البيئة لإدارة الإعدادات الحساسة.

تختلف درجة تفعيل واكتمال بعض آليات الحماية بحسب إعدادات بيئة التشغيل، ولذلك يجب مراجعتها واختبارها قبل استخدام النظام في بيئة إنتاجية.

تشغيل نسخة Windows

تتوفر نسخة مخصصة لنظام Windows من خلال صفحة الإصدارات:

"تحميل إصدارات المشروع" (https://github.com/Wusa01/Chad_Civil_Registry/releases)

بعد تشغيل البرنامج، يبدأ خادم التطبيق محلياً وتُفتح الواجهة في متصفح الإنترنت الافتراضي على العنوان:

"http://127.0.0.1:5000/"

النسخة المجهزة مخصصة لتسهيل تشغيل التطبيق للمستخدم النهائي دون الحاجة إلى تثبيت Python أو تنفيذ أوامر التشغيل يدوياً.

«ملاحظة: تشغيل التطبيق على العنوان المحلي لا يعني إتاحته تلقائياً للأجهزة الأخرى على الشبكة.»

إعداد بيئة التطوير

1. استنساخ المستودع

git clone https://github.com/Wusa01/Chad_Civil_Registry.git
cd Chad_Civil_Registry

2. إنشاء بيئة افتراضية

python -m venv venv

تفعيل البيئة الافتراضية على Linux:

source venv/bin/activate

وعلى Windows:

venv\Scripts\activate

3. تثبيت المكتبات

pip install -r requirements.txt

4. إعداد متغيرات البيئة

أنشئ نسخة من ملف الإعدادات النموذجي:

على Linux:

cp .env.example .env

على Windows:

copy .env.example .env

ثم راجع القيم الموجودة في ملف ".env" واضبطها وفق بيئة التشغيل.

لا تضع كلمات المرور أو المفاتيح السرية داخل المستودع.

5. تهيئة قاعدة البيانات

إذا كانت قاعدة البيانات تستخدم Flask-Migrate، يمكن تطبيق الترحيلات بالأوامر التالية:

flask db upgrade

6. تشغيل التطبيق

python run.py

بعد التشغيل، افتح المتصفح على:

"http://127.0.0.1:5000/"

الاختبارات

إذا كانت بيئة المشروع مجهزة للاختبارات باستخدام pytest، يمكن تشغيلها بالأمر:

pytest

ينبغي إجراء الاختبارات بعد تثبيت المتطلبات وإعداد قاعدة البيانات وملف البيئة.

النسخ الاحتياطي

يتضمن المشروع وحدة مخصصة للنسخ الاحتياطي ضمن مسارات النظام، ويمكن الوصول إلى الوظائف المرتبطة بها من خلال واجهة التطبيق بحسب صلاحيات المستخدم وإعدادات التشغيل.

ينبغي الاحتفاظ بنسخ احتياطية دورية في موقع منفصل عن قاعدة البيانات الأساسية، واختبار إمكانية استعادتها بصورة منتظمة.

ملاحظات قبل الاستخدام الإنتاجي

هذا المشروع نموذج تقني قابل للتطوير، واستخدامه في بيئة حقيقية تتطلب مراجعة واختباراً إضافياً، خصوصاً في الجوانب التالية:

- مراجعة صلاحيات المستخدمين والتحقق من الوصول.
- اختبار آليات المصادقة وحماية الجلسات.
- تأمين قاعدة البيانات والنسخ الاحتياطية.
- إعداد HTTPS وبيئة استضافة مناسبة.
- اختبار إنشاء الوثائق والتحقق منها.
- مراجعة سياسات حماية البيانات الشخصية.
- اختبار الأداء والاستقرار مع أحجام بيانات مختلفة.

التطوير المستقبلي

من المجالات التي يمكن العمل عليها في الإصدارات القادمة:

- تحسين تجربة استخدام بوابة المواطنين.
- تطوير إدارة مراكز السجل المدني والمناطق.
- تحسين التقارير والإحصائيات المدنية.
- تعزيز آليات التحقق من الوثائق.
